- **settle** — cold layout: a fresh payload annealed until the engine cools
- **steady** — settled graph repainting — the floor every other number sits on
- **drag-node** — dragging a node: hit test, reheat and re-layout every frame
- **pan** — panning the background: no layout work, pure redraw at a new transform
- **zoom** — wheel zoom: every screen-space size recomputed per frame
- **isolate** — isolating a neighbourhood: the whole graph repainted into a wash
- **add-papers** — a build phase landing: a bigger payload over a settled graph
- **filter** — moving the confidence slider: an already-built graph re-filtered

**best** is the fastest repeat, not the median: interference can only
add time to a frame, never remove it, so the fastest run is the least
contaminated. **noise** is the spread across repeats of this same
build — a delta smaller than ±8% has not been measured.

A scenario whose own behaviour varies frame to frame carries high
noise honestly: `isolate` toggles the wash on and off, and a dimmed
graph draws no labels at all, so how many frames of a repeat
were dimmed moves its median. Compare it only against itself.

## What each performance switch bought

Change in frame time against the baseline — which is the scenario table
above, measured in the same session and **interleaved** with every variant
below it, so a machine that gets busier partway through taxes all of them
equally instead of only the ones that ran late.

`~` is inside the ±8% two runs of the same build drift by: the switch
was not measured to do anything. `·` is a scenario the switch cannot touch
and did not run — a switch that changes only what is *painted* cannot move
what a layout costs, and running it there would spend fifteen seconds a
repeat to measure the noise floor.
